# A-biologically-informed-AI-framework-for-stratifying-cancer-patients

Cancer exhibits profound heterogeneity at genetic, epigenetic, and clinical levels, complicating accurate diagnosis, prognosis, and treatment. While large-scale initiatives like The Cancer Genome Atlas (TCGA) offer rich multi-omics datasets, integrative analysis remains challenging due to data sparsity, noise, and high dimensionality. Existing deep learning methods often ignore underlying gene regulatory structures and lack biological interpretability. Here, we propose a biologically informed, community-aware multimodal framework for stratifying patients across 31 cancer types. We construct cancer-specific gene regulatory networks by integrating TCGA transcriptomic and epigenomic data with known interactions from the OmniPath database. Gene communities are identified via the Spinglass algorithm and encoded using a customized autoencoder with a modality-wise self-attention mechanism, enabling dynamic integration of gene expression and DNA methylation. This modular design yields interpretable, low-dimensional embeddings for each patient, supporting robust stratification and survival analysis. Our results demonstrate improved biological coherence, scalability, and clinical relevance compared to conventional models, highlighting the potential of community-based multimodal learning in precision oncology.

# Overview of processing
**1.Get General disease network with Omnipath and create cancer-specific network**  
By using ```gen_network_2.Rmd``` and ```gen_network_1.Rmd``` to create general disease network,and during the data processing the network vertex and edge have been created.After the construction of the general (global) interaction network consisting of all edges and vertices, cancer-specific networks were generated by incorporating cancer-specific differential expression analysis results and Pearson correlation coefficients, allowing for the creation of networks that reflect the unique molecular characteristics of each cancer type. In addition to the final network results, intermediate data generated during the pipeline including the Pearson correlation coefficients used to compute edge weights were also saved as separate CSV files.  

Use shell script to exectute the R script :  
- ```r
  sbatch network_2.sh /scratch/project_2010544/R_test/network/gen_network_2.Rmd (This script is used for obtaining 15 cancers-specific network)
  ```
  
- ```r
  sbatch network_1.sh /scratch/project_2010544/R_test/network/gen_network_1.Rmd (This script is used for obtaining 18 cancers-specific network)
  ```
**2.Cancer network community through spinglass algorithm**

```sbatch network_community.sh $cancer_type``` ,the script calls the file ```cancer_network_processing.R```. The script of ```cancer_network_processing.R``` is used for cancer specific network communities creating via Spinglass algorithm.
  
**3.Preparation of TCGA data**  
Execute the shell script to trigger the R file ```omicsdata_handing.R``` implement the functionality:

sbatch omicsdata_handing.sh

**4.Execute AI model for training**  
The following shell script processes data for 31 cancer types to compute module weights and community scores. Before running run_autoencoder_1.sh, extract the 25 hyperparameter files from hyperpara/hyperpara.zip. Each .pkl file in the archive corresponds to one set of hyperparameters. These files are used as input in `autoencoder_1.py` and used in `autoencoder_shap_1.py` as input in the following step **5** as well.

```r
sh run_autoencoder_1.sh $cancer_name_features_file $test_trial_number
eg:sh run_autoencoder_1.sh /projappl/project_2010541/data/python_related/data/PCPG_selected_features.csv  11
```   


The following information illustrates the execution flow of the script ```run_autoencoder_1.sh```:

- ```run_autoencoder_1.sh``` first calls ```prepara.sh```, which prepares the environment and through path name handing the cancer name and test trial number can be provided as input for the next steps.

- These variables (e.g., cancer type, trial number, model path) are then passed to ```script_autoencoder_1.sh```, a SLURM batch submission script.

- The SLURM script submits jobs that execute ```autoencoder_1.py```, which performs model inference and score profile computation.
